Mobile Rental Platform

Havener — мобильная платформа для аренды жилья. Цель — упростить весь путь от поиска до бронирования для гостей и хозяев.

Роль
UX/UI Product Designer
Платформа
Mobile app (iOS / Android)
Фокус
UX, UI, Information Architecture, Visual Design

Контекст

Рынок аренды жилья предлагает огромное количество вариантов, однако сам процесс поиска и бронирования часто остается сложным и фрагментированным.

Пользователям приходится переключаться между десятками объявлений, сравнивать характеристики вручную и проходить длинный путь до принятия решения.

Особенно заметна эта проблема на мобильных устройствах, где количество информации значительно превышает доступное пространство экрана.

Проблема

Большинство платформ строятся вокруг каталогов недвижимости.

Пользователь сталкивается с несколькими сложностями:

  • перегруженные списки объектов;
  • сложный процесс сравнения вариантов;
  • избыток информации на ранних этапах;
  • большое количество шагов до бронирования;
  • отсутствие ощущения контроля над процессом.

В результате поиск жилья превращается в длительный и утомительный процесс.

Анализ конкурентов

Сильные стороны

  • Поддержка нескольких языков и международных рынков, что редко встречается среди специализированных сервисов недвижимости.

Ключевые выводы исследования

После анализа конкурентов были выявлены несколько повторяющихся паттернов:

Информационная перегрузка

Большинство платформ пытаются показать пользователю максимально возможное количество информации на ранних этапах взаимодействия.

Сложность сравнения объектов

Пользователям приходится самостоятельно сопоставлять характеристики жилья между несколькими карточками и экранами.

Длинный путь до принятия решения

Процесс аренды часто состоит из большого количества промежуточных шагов и переключений между экранами.

Фокус на данных вместо опыта

Большинство решений эффективно помогают искать объекты, но уделяют меньше внимания самому процессу принятия решения.

На основе анализа было принято решение сосредоточиться не на увеличении количества функций, а на улучшении пользовательского опыта.

Основными направлениями стали:

  • сокращение когнитивной нагрузки;
  • упрощение сравнения объектов;
  • уменьшение количества шагов до бронирования;
  • повышение прозрачности процесса;
  • создание более предсказуемого и комфортного мобильного опыта.

Цель проекта

Создать мобильный опыт, который позволяет:

  • быстрее находить подходящие варианты;
  • упростить процесс принятия решений;
  • сократить путь до бронирования;
  • сделать взаимодействие более предсказуемым;
  • повысить уверенность пользователя на каждом этапе.

Исследование

На старте проекта была проведена декомпозиция пользовательского пути арендатора.

Были выделены ключевые этапы:

  1. Поиск жилья.
  2. Просмотр вариантов.
  3. Сравнение объектов.
  4. Принятие решения.
  5. Бронирование.

Анализ показал, что наибольшее количество потерь внимания происходит между этапами просмотра объектов и принятием решения.

Именно этот участок пользовательского пути стал основным фокусом проекта.

User Flow

Для Havener пользовательский сценарий был разделён на два ключевых этапа:

  1. Поиск жилья (Searching Process)
  2. Бронирование и проживание (Booking Process)

Такое разделение позволило сосредоточиться на двух основных задачах пользователя: найти подходящий вариант и успешно завершить аренду.

Процесс поиска жилья

Цель

Помочь пользователю быстро находить подходящие варианты жилья с помощью удобного поиска, фильтрации и персонализированных рекомендаций.

1. Первое знакомство с приложением

Пользователь открывает приложение и проходит краткий онбординг.

На этом этапе демонстрируются основные возможности платформы:

  • поиск актуальных объектов;
  • настройка фильтров;
  • сохранение понравившихся вариантов;
  • запись на просмотры;
  • общение с владельцами жилья.

После знакомства пользователь переходит к началу работы с платформой.

2. Авторизация

Для максимального снижения барьеров входа предусмотрено несколько сценариев:

  • вход через Google;
  • вход по электронной почте;
  • регистрация нового аккаунта;
  • гостевой режим без регистрации.

Такой подход позволяет пользователю начать поиск жилья практически сразу.

3. Поиск недвижимости

Пользователь может начать поиск несколькими способами:

Через поисковую строку

Поиск по району, адресу или городу.

Через быстрые фильтры

Настройка параметров:

  • стоимость аренды;
  • район;
  • наличие животных;
  • количество комнат;
  • тип жилья.

Через карту

Переключение между режимами:

  • список объектов;
  • карта объектов.

4. Работа с результатами

После настройки параметров пользователь получает список объектов.

На этом этапе доступны:

  • уточнение фильтров;
  • изменение критериев поиска;
  • просмотр карточек жилья;
  • сохранение поискового запроса.

Если результаты отсутствуют,
система предлагает рекомендации по расширению параметров поиска.

UX-решение

Поиск строится вокруг идеи:

Сначала показать релевантные варианты, затем постепенно уточнять выбор.

Это позволяет снизить когнитивную нагрузку и ускорить принятие решения.

Процесс бронирования

Цель

Сделать путь от просмотра объекта до завершения аренды максимально прозрачным и понятным.

1. Просмотр объекта

Пользователь открывает карточку недвижимости.

На странице представлены:

  • основные фотографии;
  • стоимость;
  • ключевые характеристики;
  • информация о районе;
  • условия аренды.
Длинные экраны прокручиваются внутри рамки.

2. Галерея и виртуальный тур

Для повышения доверия пользователь может изучить:

  • дополнительные фотографии;
  • виртуальный 3D-тур;
  • интерьер и планировку объекта.

Это помогает принять решение ещё до посещения жилья.

3. Отзывы

Перед бронированием пользователь может ознакомиться с отзывами.

Доступны:

  • общий рейтинг;
  • список всех отзывов;
  • подробная информация об арендодателе.

Также можно изучить историю предыдущих отзывов о владельце жилья.

4. Запрос на бронирование

После изучения объекта пользователь может:

  • связаться с владельцем;
  • назначить просмотр;
  • отправить заявку на бронирование.

5. Подтверждение бронирования

Если платёж проходит успешно:

  • бронирование подтверждается;
  • объект появляется в разделе предстоящих поездок.

Если платёж отклонён:

  • пользователь получает уведомление;
  • предлагается изменить способ оплаты.

6. Предстоящее проживание

До начала аренды пользователь может:

  • просматривать детали бронирования;
  • получать уведомления;
  • связываться с владельцем.

7. Активное проживание

Во время проживания доступны дополнительные действия:

  • связаться с владельцем;
  • продлить аренду;
  • сообщить о проблеме;
  • получить поддержку.

8. Завершение аренды

После завершения проживания пользователь может:

  • оставить отзыв;
  • сохранить объект в избранное;
  • повторно забронировать жильё.

Основные UX-принципы

На основе пользовательского сценария были сформированы четыре ключевых принципа продукта:

Быстрый старт

Поиск жилья начинается без лишних действий благодаря гостевому режиму и упрощённой регистрации.

Гибкий поиск

Пользователь может искать жильё через карту, фильтры или текстовый запрос.

Прозрачное бронирование

На каждом этапе пользователь понимает текущее состояние процесса и дальнейшие действия.

Поддержка полного цикла аренды

Платформа сопровождает пользователя не только до момента бронирования, но и во время проживания и после его завершения.

Дизайн-подход

Simplicity Over Complexity

Вместо демонстрации всех возможностей продукта одновременно интерфейс строится вокруг последовательного раскрытия информации.

Пользователь получает только те данные, которые необходимы в текущий момент времени.

Это снижает когнитивную нагрузку и ускоряет принятие решений.

Информационная архитектура

Одной из главных задач стало построение понятной структуры продукта.

Была сформирована система, которая объединяет:

  • поиск объектов;
  • фильтрацию;
  • просмотр карточек;

Каждый сценарий логически связан со следующим и поддерживает непрерывный пользовательский поток.

Главный экран

Главный экран выступает точкой входа в продукт.

Основная задача — помочь пользователю быстро сформулировать запрос и перейти к поиску жилья.

Приоритет был отдан:

  • понятной структуре;
  • крупным действиям;
  • быстрому старту поиска.

Каталог объектов

Каталог был спроектирован как инструмент принятия решений, а не просто список объявлений.

Каждая карточка содержит только наиболее важную информацию:

  • стоимость;
  • расположение;
  • рейтинг;
  • фотографии;
  • ключевые характеристики.

Такой подход позволяет быстрее оценивать варианты и сокращает время на просмотр.

Визуальная система

Визуальный язык проекта строится вокруг ощущения простоты, надежности и комфорта.

Основные характеристики:

  • минималистичный интерфейс;
  • спокойная цветовая палитра;
  • акцент на контенте;
  • крупная типографика;
  • высокая читаемость.

Главным визуальным элементом становятся сами объекты недвижимости и контекст их использования.

Дизайн-система

Для обеспечения консистентности интерфейса была сформирована базовая дизайн-система.

Она включает:

  • типографическую шкалу;
  • систему цветов;
  • набор компонентов;
  • правила построения экранов;
  • состояния интерфейса.

Это позволяет масштабировать продукт и поддерживать единый пользовательский опыт.

Результат

Пользовательский путь сведён к двум чётко разделённым этапам — поиску и бронированию — вместо единого перегруженного сценария, характерного для Zillow или Trulia.

Ключевое решение основано на выводе из анализа пути: наибольшая потеря внимания происходит между просмотром объекта и принятием решения. Именно этот участок получил наибольшую детализацию — галерея, 3D-тур, отзывы и история арендодателя доступны прямо на карточке объекта, без перехода на отдельные экраны.

Гостевой режим и вход в один клик убирают барьер входа до начала поиска. Дизайн-система, выстроенная поверх этого флоу, делает решение воспроизводимым для новых экранов, а не разовым макетом.
